# Gözleme coding-agent operating model

Read `CLAUDE.md`, `.gozleme/manifest.yaml`, the confirmed architecture baseline, security invariants and the current registry before acting. `drive-speckit` loads `docs/prompts/const.md` with the installed constitution workflow and `docs/prompts/spec-nnnn.md` for `/speckit.specify`; use native Spec Kit templates, not custom ones. Work in allowed branches. Track stage in per-spec progress and central YAML; generate human register from it.

Stages: verify prerequisites → specify → plan → tasks → implement → tests → autonomously drive demo and screenshot → converge (bounded retries) → **automatically** invoke Spec Impact Analyst → propagate evidence-based downstream prompt changes within authority → Roadmap Steward synchronize and validate registry/human register → prepare PR → stop for human merge. `drive-speckit` may make three meaningful repair attempts per distinct failure before blocking; do not auto-converge recursively, never silently weaken failing security checks. If analysis discovers a defect, start bounded corrective cycle and rerun affected evidence.

Future unimplemented prompt files are living documents: Agent may directly edit them, dependencies and demos based on real code/API/schema decisions consistent with the approved baseline, recording finding IDs and rationale. Confirmed architecture/security constraints, committed MVP scope and approved completed specs cannot be silently changed: produce change proposal for human approval. Already merged specs are historical evidence; use additive amendment/corrective PR rather than overwriting them. Agent never merges or enables auto-merge. Agent must not claim merged status without verified human merge.
