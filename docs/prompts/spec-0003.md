## Starting prompt for `/speckit.specify`

Build **Tenant RLS and visibility scaffolding** as one bounded, runnable, tested vertical slice of the open-source **Gözleme** federated AI capability registry.

**User-visible outcome:** Exercise two tenants through UI/API and demonstrate unauthorized cross-tenant access denied.

**In scope:** Transaction-scoped tenant context; RLS, DB privilege boundaries, negative tests.

**Important boundary:** Never rely on caller-set session variables as trusted identity.

Respect the authoritative `docs/architecture/architecture-baseline.md`, `docs/architecture/security-invariants.md`, `docs/decisions/consistency-review.md`, `.gozleme/manifest.yaml`, and spec registry. Use the already installed Spec Kit workflow, its native templates, and confirmed architecture decisions. Do not re-create Spec Kit templates or reinstall Spec Kit. Do not claim unimplemented post-MVP security guarantees.

### Implementation alignment (GOZ-0000-IF-03, IF-09, IF-10, 2026-11-14)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0000 at commit `e7904ad` (findings in `docs/specs/000-repository-bootstrap/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 1 → 2. These bullets record implemented foundation facts and the obligations they create within confirmed architecture; they do not change scope or security invariants._

- (IF-03) Role facts: `gozleme_app` is `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS NOINHERIT`; `gozleme_migrator` is `NOSUPERUSER NOBYPASSRLS` and owns the database, schema `gozleme` and every table it creates. The foundation migration sets default privileges so every new `gozleme` table is automatically granted `SELECT, INSERT, UPDATE, DELETE` to `gozleme_app`. No RLS policy or tenant context exists yet. Table owners bypass RLS unless `FORCE ROW LEVEL SECURITY` is set, and the migrator owns every table, so the effective boundary is the non-owner `gozleme_app`; decide explicitly whether to FORCE RLS and test both roles. Because default privileges grant DML immediately, a tenant-owned table must get `ENABLE ROW LEVEL SECURITY` and its policies in the same migration that creates it; add a catalog test that fails if any tenant-owned `gozleme` table lacks `relrowsecurity` (and `relforcerowsecurity` if chosen). Retrofit RLS onto the tenant-owned tables introduced by GOZ-0001 and GOZ-0002.
- (IF-03) Verified on the GOZ-0000 stack: `gozleme_app` can `SET LOCAL` arbitrary custom settings (for example `app.tenant_id`). A transaction-scoped tenant setting is therefore defence in depth, not identity; tests must show a caller-set value cannot widen access beyond application-verified membership.
- (IF-09) Reuse `tests/Gozleme.Api.IntegrationTests/Infrastructure/GozlemeDatabase.cs` (starts PostgreSQL, applies `01-roles.sh`, runs the real migrator; exposes `SuperuserConnectionString`, `MigratorConnectionString`, `AppConnectionString`) and `GozlemeApiFactory`. `GozlemeDatabase.ScalarAsync` defaults to the superuser connection, which bypasses RLS: isolation and leak tests must use `AppConnectionString` or the API. The assembly-wide `PgvectorDatabaseFixture` database is shared, so mutating tests need isolated data or their own `GozlemeDatabase`.
- (IF-10) Database roles are created only by `deploy/postgres/init/01-roles.sh` on a fresh data volume (Helm: operator prerequisite in `deploy/helm/gozleme/README.md`); `gozleme_migrator` is `NOCREATEROLE` and cannot create roles from a migration. Any new role must be added there and in the Helm README, and requires `make reset` on existing local volumes.

### Observability (foundational, GOZ-0000-IF-11, 2026-11-14)

_Provenance: maintainer decision 2026-11-14 that OpenTelemetry is foundational across all work, including browser telemetry; implemented in GOZ-0000 commit `ba6f28c`. Added by the Spec Impact Analyst; Roadmap Steward records the prompt revision. This adds a cross-cutting engineering requirement only; scope, boundaries and security invariants are unchanged._

- Instrument new server code paths with spans and metrics via `GozlemeTelemetry.ActivitySource` / `GozlemeTelemetry.Meter` (name `Gozleme.Api`, registered by `AddGozlemeTelemetry` in `src/Gozleme.Api/Telemetry/GozlemeTelemetry.cs`) and new UI flows via the browser tracer (`web/src/telemetry/browser.ts`); use `gozleme.*` names for custom spans, attributes and metrics, and do not add a second telemetry pipeline.
- Preserve the single browser → web → API → PostgreSQL trace (W3C context; the web tier propagates only to `GOZLEME_API_URL`). Export stays optional (`OTEL_EXPORTER_OTLP_ENDPOINT`), and the collector and Jaeger are never health dependencies.
- Secrets, credentials, tokens, personal data and private or tenant-confidential metadata never enter span names, attributes, events, metric labels or exported logs (invariant 8; GOZ-0000-IF-21). Instrumentation already records `db.query.text`, `http.url`/`http.target` and `user_agent.original`, so keep confidential values out of SQL text (parameters only) and out of URLs. The collector redaction in `deploy/otel/collector.yaml` is defence in depth only. Keep metric label cardinality bounded.
- Assert this spec's key spans and metrics in integration tests (pattern: `tests/Gozleme.Api.IntegrationTests/TelemetryTests.cs`) and in the demo (pattern: `observability` test in `e2e/tests/bootstrap-demo.spec.ts`, Jaeger on `:16686`), including a no-secret check of captured telemetry.
- Spec focus: a span or event when tenant context is established and cleared per transaction, plus an RLS/authorization denial counter. Telemetry backends are operator-visible and cross-tenant (R3-19), so decide explicitly whether an opaque tenant ID may be a span attribute, and never record tenant-confidential values (GOZ-0000-IF-21).

### Identity and session conventions (GOZ-0001-IF-01, IF-02, IF-09, IF-11, IF-17, 2026-11-15)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0001 at commit `d2e5c6c` (findings in `docs/specs/001-local-identity/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 2 → 3. These bullets record implemented identity facts and the obligations they create within confirmed architecture; they do not change scope, boundaries, prerequisites or security invariants._

- (IF-02) Product pages and API endpoints require a signed-in session by default. Every `/api/v1` endpoint is mapped on the route group in `src/Gozleme.Api/GozlemeApp.cs`, which calls `.RequireAuthorization()`. An endpoint is anonymous only through an explicit `.AllowAnonymous()` that this spec decides and documents. `tests/Gozleme.Api.IntegrationTests/EndpointAuthorizationTests.cs` fails on any endpoint without an authorization decision and pins the exact anonymous list, so update that list deliberately. Map new endpoints on that group, never on `app` directly. Pages are not protected by default: each new page must gate server-side with `getSession()` (`web/src/lib/session.ts`, pattern `web/src/app/page.tsx`; there is no `proxy.ts`). Add an anonymous-rejection test for every new endpoint and page.
- (IF-01) Cross-site request protection has two layers. API: `WebClientHeaderFilter` (`src/Gozleme.Api/Identity/WebClientHeaderFilter.cs`) runs on the whole `/api/v1` group and requires `x-gozleme-client: web` on every unsafe method, so new endpoints get it automatically. Web tier: every new unsafe (non-GET) browser-facing route handler must call `isSameOrigin()` (`web/src/lib/origin.ts`) before `forwardToApi()` (`web/src/lib/api.ts`). `forwardToApi` always adds the API header, so the web-tier check is the browser-facing boundary and is still opt-in per route. The browser reaches the API only through Next.js route handlers (no CORS).
- (IF-17) PostgreSQL outages fail closed for every endpoint through `UseDatabaseUnavailableResponses` (`src/Gozleme.Api/DatabaseUnavailable.cs`), which answers `503 {"error":"unavailable"}`. Do not catch Npgsql connection failures in endpoint code. The web helper maps any API status of 500 or above to 503.
- (IF-09) Cumulative demo:
  - Add a Playwright project `goz-NNNN` that depends on the previous spec's project (`e2e/playwright.config.ts`) and a `specDirs` entry (`e2e/tests/evidence.ts`).
  - CI (`.github/workflows/ci.yml`) and `make demo` with no `SPEC` run the highest-numbered spec that has a Playwright project, so adding the project is enough.
  - Earlier suites write their screenshots to this spec's `evidence/screenshots/regression-goz-NNNN/`.
  - Seeded synthetic accounts are `alice`, `bob` and `lockout@demo.gozleme.test`, with password `GOZLEME_DEMO_PASSWORD`. `alice`'s signed-in browser state is `.demo-tmp/alice-storage-state.json`, subject to the 30-minute idle expiry.
  - The GOZ-0001 suite leaves every `bob` session revoked and `lockout@` locked for 15 minutes, so later suites sign in afresh and never rely on `lockout@`.
  - Extend the idempotent `seed` command (`src/Gozleme.Api/Identity/OperatorCommands.cs`) for new synthetic fixtures. Never seed through migrations.
- (IF-11) Refer to people only by the opaque account id (`ClaimTypes.NameIdentifier`, a UUIDv7), never by email, in telemetry, audit events, URLs and screenshots. Security-relevant events use the `Gozleme.Security.Audit` log category (`src/Gozleme.Api/Identity/SecurityAudit.cs`). Those are log records, bounded by retention and deleted by `make reset`, not a durable audit store.

### Implementation alignment (GOZ-0001-IF-03, IF-04, 2026-11-15)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0001 at commit `d2e5c6c` (findings in `docs/specs/001-local-identity/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 2 → 3. These bullets record implemented identity facts and the obligations they create within confirmed architecture; they do not change scope, boundaries, prerequisites or security invariants._

- (IF-03) Correction to the GOZ-0000-IF-03 bullet above: GOZ-0001 introduced **no** tenant-owned tables (FR-034). `users`, `user_claims`, `user_logins`, `user_tokens`, `auth_sessions` and `data_protection_keys` are global identity infrastructure. Classify them in an explicit allow-list of non-tenant tables in the RLS catalog test instead of giving them tenant RLS. Retrofit only the GOZ-0002 tenant-owned tables.
- (IF-03) Session resolution runs before any tenant context exists. `DbTicketStore` and `SessionPrincipalValidator` open their own contexts through `IDbContextFactory<GozlemeDbContext>` on the shared `gozleme_app` pool (`DbTicketStore.cs:17-21, 101-103`). Operator commands and `seed` run as `gozleme_app` with no HTTP request (`OperatorCommands.cs:43-44`). Tenant context must be transaction-scoped (`SET LOCAL`/`set_config(..., true)`), must never be required for identity lookups, and must never persist on a pooled connection. Test that an identity lookup on a connection previously used with tenant A carries no tenant A context.
- (IF-04) Derive the tenant from application-verified membership in the database on each request, never from session-ticket claims (frozen at sign-in) or from a caller-supplied header or setting.
