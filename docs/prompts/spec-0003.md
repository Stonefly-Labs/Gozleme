### Implementation alignment (GOZ-0000-IF-03, IF-09, IF-10, 2026-11-14)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0000 at commit `e7904ad` (findings in `docs/specs/000-repository-bootstrap/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 1 → 2. These bullets record implemented foundation facts and the obligations they create within confirmed architecture; they do not change scope or security invariants._

- (IF-03) Role facts: `gozleme_app` is `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS NOINHERIT`; `gozleme_migrator` is `NOSUPERUSER NOBYPASSRLS` and owns the database, schema `gozleme` and every table it creates. The foundation migration sets default privileges so every new `gozleme` table is automatically granted `SELECT, INSERT, UPDATE, DELETE` to `gozleme_app`. No RLS policy or tenant context exists yet. Table owners bypass RLS unless `FORCE ROW LEVEL SECURITY` is set, and the migrator owns every table, so the effective boundary is the non-owner `gozleme_app`; decide explicitly whether to FORCE RLS and test both roles. Because default privileges grant DML immediately, a tenant-owned table must get `ENABLE ROW LEVEL SECURITY` and its policies in the same migration that creates it; add a catalog test that fails if any tenant-owned `gozleme` table lacks `relrowsecurity` (and `relforcerowsecurity` if chosen). Retrofit RLS onto the tenant-owned tables introduced by GOZ-0001 and GOZ-0002.
- (IF-03) Verified on the GOZ-0000 stack: `gozleme_app` can `SET LOCAL` arbitrary custom settings (for example `app.tenant_id`). A transaction-scoped tenant setting is therefore defence in depth, not identity; tests must show a caller-set value cannot widen access beyond application-verified membership.
- (IF-09) Reuse `tests/Gozleme.Api.IntegrationTests/Infrastructure/GozlemeDatabase.cs` (starts PostgreSQL, applies `01-roles.sh`, runs the real migrator; exposes `SuperuserConnectionString`, `MigratorConnectionString`, `AppConnectionString`) and `GozlemeApiFactory`. `GozlemeDatabase.ScalarAsync` defaults to the superuser connection, which bypasses RLS: isolation and leak tests must use `AppConnectionString` or the API. The assembly-wide `PgvectorDatabaseFixture` database is shared, so mutating tests need isolated data or their own `GozlemeDatabase`.
- (IF-10) Database roles are created only by `deploy/postgres/init/01-roles.sh` on a fresh data volume (Helm: operator prerequisite in `deploy/helm/gozleme/README.md`); `gozleme_migrator` is `NOCREATEROLE` and cannot create roles from a migration. Any new role must be added there and in the Helm README, and requires `make reset` on existing local volumes.
