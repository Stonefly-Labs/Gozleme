### Implementation alignment (GOZ-0000-IF-04, 2026-11-14)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0000 at commit `e7904ad` (findings in `docs/specs/000-repository-bootstrap/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 1 → 2. These bullets record implemented foundation facts and the obligations they create within confirmed architecture; they do not change scope or security invariants._

- (IF-04) Foundation default privileges grant `UPDATE` and `DELETE` on every new `gozleme` table to `gozleme_app`. Tables that must be immutable or append-only need the creating migration to `REVOKE UPDATE, DELETE` (or enforce equivalently) for `gozleme_app`, with an integration test as `gozleme_app` proving the database rejects mutation, in addition to API-level checks. This applies to authorization receipts and epoch history here.

### Observability (foundational, GOZ-0000-IF-11, 2026-11-14)

_Provenance: maintainer decision 2026-11-14 that OpenTelemetry is foundational across all work, including browser telemetry; implemented in GOZ-0000 commit `ba6f28c`. Added by the Spec Impact Analyst; Roadmap Steward records the prompt revision. This adds a cross-cutting engineering requirement only; scope, boundaries and security invariants are unchanged._

- Instrument new server code paths with spans and metrics via `GozlemeTelemetry.ActivitySource` / `GozlemeTelemetry.Meter` (name `Gozleme.Api`, registered by `AddGozlemeTelemetry` in `src/Gozleme.Api/Telemetry/GozlemeTelemetry.cs`) and new UI flows via the browser tracer (`web/src/telemetry/browser.ts`); use `gozleme.*` names for custom spans, attributes and metrics, and do not add a second telemetry pipeline.
- Preserve the single browser → web → API → PostgreSQL trace (W3C context; the web tier propagates only to `GOZLEME_API_URL`). Export stays optional (`OTEL_EXPORTER_OTLP_ENDPOINT`), and the collector and Jaeger are never health dependencies.
- Secrets, credentials, tokens, personal data and private or tenant-confidential metadata never enter span names, attributes, events, metric labels or exported logs (invariant 8; GOZ-0000-IF-21). Instrumentation already records `db.query.text`, `http.url`/`http.target` and `user_agent.original`, so keep confidential values out of SQL text (parameters only) and out of URLs. The collector redaction in `deploy/otel/collector.yaml` is defence in depth only. Keep metric label cardinality bounded.
- Assert this spec's key spans and metrics in integration tests (pattern: `tests/Gozleme.Api.IntegrationTests/TelemetryTests.cs`) and in the demo (pattern: `observability` test in `e2e/tests/bootstrap-demo.spec.ts`, Jaeger on `:16686`), including a no-secret check of captured telemetry.
- Spec focus: epoch bump and receipt issuance spans and metrics. Telemetry is not the audit record; receipts remain authoritative in PostgreSQL and may reference a trace ID only.

### Stored telemetry (GOZ-0000-IF-22, IF-25, IF-26, 2026-11-14)

_Provenance: maintainer decision 2026-11-14 to store searchable telemetry, at least on the local stack; implemented in GOZ-0000 commit `9c6d32d`. Added by the Spec Impact Analyst. This is additive and changes no scope or invariant._

- (IF-22) Local Compose stores logs in Loki (volume `lokidata`, OTLP via the collector, `trace_id` structured metadata, 7-day retention) and metrics in Prometheus (volume `promdata`, 7 days); Grafana on `127.0.0.1:3001` links logs and traces. Traces stay in Jaeger's in-memory storage and are lost on restart. `make reset` deletes all of these volumes. Helm ships no telemetry backends; operators provide OTLP backends. Authorization receipts, epochs and governance change events must remain authoritative in PostgreSQL. They must never depend on retention-bounded or resettable telemetry stores, and stored logs are not an audit trail.
