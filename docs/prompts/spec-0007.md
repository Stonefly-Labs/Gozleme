### Implementation alignment (GOZ-0000-IF-01, IF-04, IF-13, 2026-11-14)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0000 at commit `e7904ad` (findings in `docs/specs/000-repository-bootstrap/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 1 → 2. These bullets record implemented foundation facts and the obligations they create within confirmed architecture; they do not change scope or security invariants._

- (IF-04) Foundation default privileges grant `UPDATE` and `DELETE` on every new `gozleme` table to `gozleme_app`. Tables that must be immutable or append-only need the creating migration to `REVOKE UPDATE, DELETE` (or enforce equivalently) for `gozleme_app`, with an integration test as `gozleme_app` proving the database rejects mutation, in addition to API-level checks. This applies to signed revisions and attestations here.
- (IF-13) Deployment conventions: Helm runs containers with `readOnlyRootFilesystem: true` and only `/tmp` (emptyDir) writable; secrets reach pods only through Secrets referenced by name (pattern: `database.existingSecret` with keys `app-connection-string`, `migrator-connection-string`), never chart values. Compose services bind host ports to `127.0.0.1`, take overridable `GOZLEME_*` variables and keep throwaway local defaults in `.env.example`. Signing key material follows the same Secret-reference convention and never appears in values, logs or screenshots.
- (IF-01) If `POST /api/v1/publish` is introduced here, narrow the GOZ-0000 boundary assertion for it (`tests/Gozleme.Api.IntegrationTests/BootstrapBoundaryTests.cs`) rather than removing the suite.
