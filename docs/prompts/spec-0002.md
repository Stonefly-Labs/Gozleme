These bullets record implemented foundation facts and the obligations they create within confirmed architecture; they do not change scope or security invariants._

- (IF-01) GOZ-0000 boundary tests (`tests/Gozleme.Api.IntegrationTests/BootstrapBoundaryTests.cs`, `boundary` test in `e2e/tests/bootstrap-demo.spec.ts`) assert 404 for `GET /api/v1/organizations` and the `/organizations` page. This spec must narrow only those assertions it legitimately supersedes, keep the remaining ones, and add its own boundary test (no full administrative delegation); never delete or weaken the suite wholesale.
- (IF-03) Role facts: `gozleme_app` is `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS NOINHERIT`; `gozleme_migrator` is `NOSUPERUSER NOBYPASSRLS` and owns the database, schema `gozleme` and every table it creates. The foundation migration sets default privileges so every new `gozleme` table is automatically granted `SELECT, INSERT, UPDATE, DELETE` to `gozleme_app`. No RLS policy or tenant context exists yet. Organization and membership tables created here are therefore DML-accessible to `gozleme_app` before RLS exists; keep authorization in the application layer and shape tables with explicit tenant key columns so GOZ-0003 can enable RLS on them without a breaking data migration.
