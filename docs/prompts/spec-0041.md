## Starting prompt for `/speckit.specify`

Build **External OpenID Connect sign-in and account linking** as one bounded, runnable, tested vertical slice of the open-source **Gözleme** federated AI capability registry.

**User-visible outcome:** An operator configures an OIDC provider. A person signs in with it, lands on the protected dashboard with a Gözleme session, links the external identity to an existing local account from a signed-in session, and later signs in either way.

**In scope:**
- Operator-configured OIDC providers (authorization code flow with PKCE), off by default.
- A local, offline test provider in Compose under an opt-in profile for development and the demo.
- Sign-in, just-in-time account creation (operator toggle) and explicit account linking.

**Important boundary:** Compose and Helm stay runnable with no external identity provider configured or reachable, and the sign-in page offers only local sign-in until an operator configures a provider. External identity never bypasses lockout, revocation or the per-request session checks built in GOZ-0001.

### Feature-specific requirements (from GOZ-0001 implementation evidence)

- **Providers.**
  - Configure providers under `Gozleme:Auth:Oidc:*` (authority, client id, scopes, display name). Client secrets are secret references (Helm `existingSecret` pattern, GOZ-0000-IF-13), never chart values, manifests or logs.
  - Validate issuer, audience, signature, `nonce` and `state`; use PKCE; reject unsigned or `none`-algorithm tokens. Discovery and JWKS fetches are bounded in time and size and never make the provider a health dependency.
  - The local test provider runs only under a Compose profile (for example `--profile oidc`), bound to `127.0.0.1`, with throwaway synthetic users. Default `docker compose up` contacts no identity provider.
- **Accounts and linking.**
  - Store external logins in the existing `gozleme.user_logins` table (created empty in GOZ-0001; `NoExternalIdentityTests` asserts it is empty), keyed by issuer and subject, never by email.
  - Never auto-link an external identity to an existing account by matching email, unless the email is verified on both sides (GOZ-0040) and the operator enables it. The default link path is an explicit "link" action from a signed-in local session (GOZ-0001-IF-05).
  - Just-in-time account creation is an operator toggle that respects `GOZLEME_REGISTRATION_ENABLED`.
- **Sessions.** External sign-in issues the same `gozleme_session` cookie through the existing `DbTicketStore`, retires any prior session (fixation protection, `AuthEndpoints.cs`), honours lockout, and is revoked by sign-out-everywhere and operator reset. Provider tokens are not stored unless a later spec needs them.
- **Boundary changes.** This spec supersedes GOZ-0001 FR-028:
  - Narrow `NoExternalIdentityTests` (external paths 404, `externalProviders: []`, empty `user_logins`) to the unconfigured case only, and keep it passing when no provider is configured.
  - Callback endpoints are anonymous by design: add them to the pinned list in `EndpointAuthorizationTests` deliberately, and keep the `/api/v1` group's deny-by-default otherwise.
  - The login page lists configured providers from `/api/v1/auth/options` (`externalProviders`).
- **Abuse resistance.** Rate-limit callbacks per client within the existing `GlobalLimiter`. Treat `returnTo` with the GOZ-0001 `safeReturnTo` rules. Apply both cross-site request protection layers to any unsafe browser-facing route.
- **Privacy and observability.** Spans `gozleme.auth.oidc_sign_in` and `gozleme.auth.link`, with bounded outcome and failure categories on `gozleme.auth.attempts` (for example `state_mismatch`, `invalid_token`, `not_linked`). Never record tokens, codes, emails, subject claims or provider error text containing personal data. Audit events use `Gozleme.Security.Audit` with the opaque account id only.

### Demo acceptance

**Demo walkthrough:**
1. With the default stack, show that the sign-in page offers only local sign-in and the OIDC callback returns 404.
2. Start the opt-in test provider, sign in as a synthetic external user, and land on the protected dashboard.
3. Sign in locally, link the external identity, sign out, and sign back in with the provider into the same account.
4. Show that a forged `state`, a replayed code and a token from the wrong issuer are each refused with a generic error.

Include a test exercising the stated important boundary: no identity provider is contacted by the default stack, and an external sign-in never bypasses lockout or revocation.

**Spec complete only when:** code and tests pass; demo is autonomously run or a documented blocker explains why; convergence succeeds; downstream impact is analyzed and applied within authority; PR evidence and screenshots are ready; human merge is later verified.

### Identity and session conventions (GOZ-0001-IF-01, IF-02, IF-09, IF-11, IF-17, 2026-11-15)

- Map new endpoints on the `/api/v1` group, which requires a session and the `x-gozleme-client` header on unsafe methods by default. Callback endpoints opt out explicitly with `.AllowAnonymous()` and are added to `EndpointAuthorizationTests`. New pages gate server-side with `getSession()`. Database outages fail closed with `503 {"error":"unavailable"}`.
- Demo: add a `goz-NNNN` Playwright project depending on the previous spec's project, plus a `specDirs` entry. The runner and CI pick the latest project automatically. Extend the idempotent `seed` command for any new synthetic fixtures.

### Observability (foundational, GOZ-0000-IF-11)

- Instrument new server code paths with spans and metrics via `GozlemeTelemetry.ActivitySource` / `GozlemeTelemetry.Meter` and new UI flows via the browser tracer. Use `gozleme.*` names and do not add a second telemetry pipeline.
- Preserve the single browser → web → API → PostgreSQL trace. Calls to the provider join that trace, without token, code or claim attributes.
- Secrets, tokens and personal data never enter span names, attributes, events, metric labels or exported logs (invariant 8; GOZ-0000-IF-21).
- Assert this spec's key spans and metrics in integration tests and in the demo, including a no-secret check of captured telemetry.
