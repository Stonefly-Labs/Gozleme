## Starting prompt for `/speckit.specify`

Build **External OpenID Connect sign-in and account linking** as one bounded, runnable, tested vertical slice of the open-source **Gözleme** federated AI capability registry.

**User-visible outcome:** An operator configures an OIDC provider. A person signs in with it, lands on the protected dashboard with a Gözleme session, links the external identity to an existing local account from a signed-in session, and later signs in either way.

**In scope:**
- Operator-configured OIDC providers (authorization code flow with PKCE), off by default.
- A local, offline test provider in Compose under an opt-in profile for development and the demo.
- Sign-in, just-in-time account creation (operator toggle) and explicit account linking.

**Important boundary:** Compose and Helm stay runnable with no external identity provider configured or reachable, and the sign-in page offers only local sign-in until an operator configures a provider. External identity never bypasses lockout, revocation or the per-request session checks built in GOZ-0001.

Respect the authoritative `docs/architecture/architecture-baseline.md`, `docs/architecture/security-invariants.md`, `docs/decisions/consistency-review.md`, `.gozleme/manifest.yaml`, and spec registry. Use the already installed Spec Kit workflow, its native templates, and confirmed architecture decisions. Do not re-create Spec Kit templates or reinstall Spec Kit. Do not claim unimplemented post-MVP security guarantees.

### Feature-specific requirements (from GOZ-0001 implementation evidence)

- **Providers.**
  - Configure providers under `Gozleme:Auth:Oidc:*` (authority, client id, scopes, display name). Client secrets are secret references (Helm `existingSecret` pattern, GOZ-0000-IF-13), never chart values, manifests or logs.
  - Validate issuer, audience, signature, `nonce` and `state`; use PKCE; reject unsigned or `none`-algorithm tokens. Discovery and JWKS fetches are bounded in time and size and never make the provider a health dependency.
  - The local test provider runs only under a Compose profile (for example `--profile oidc`), bound to `127.0.0.1`, with throwaway synthetic users. Default `docker compose up` contacts no identity provider.
- **Accounts and linking.**
  - Store external logins in the existing `gozleme.user_logins` table (created empty in GOZ-0001; `NoExternalIdentityTests` asserts it is empty), keyed by issuer and subject, never by email.
  - Never auto-link an external identity to an existing account by matching email, unless the email is verified on both sides (GOZ-0040) and the operator enables it. The default link path is an explicit "link" action from a signed-in local session (GOZ-0001-IF-05).
  - Just-in-time account creation is an operator toggle that respects `GOZLEME_REGISTRATION_ENABLED`.
- **Sessions.** External sign-in issues the same `gozleme_session` cookie through the existing `DbTicketStore`, retires any prior session (fixation protection, `AuthEndpoints.cs`), honours lockout, and is revoked by sign-out-everywhere and operator reset. Provider tokens are not stored unless a later spec needs them.
- **Boundary changes.** This spec supersedes GOZ-0001 FR-028:
  - Narrow `NoExternalIdentityTests` (external paths 404, `externalProviders: []`, empty `user_logins`) to the unconfigured case only, and keep it passing when no provider is configured.
  - Callback endpoints are anonymous by design: add them to the pinned list in `EndpointAuthorizationTests` deliberately, and keep the `/api/v1` group's deny-by-default otherwise.
  - The login page lists configured providers from `/api/v1/auth/options` (`externalProviders`).
- **Abuse resistance.** Rate-limit callbacks per client within the existing `GlobalLimiter`. Treat `returnTo` with the GOZ-0001 `safeReturnTo` rules. Apply both cross-site request protection layers to any unsafe browser-facing route.
- **Privacy and observability.** Spans `gozleme.auth.oidc_sign_in` and `gozleme.auth.link`, with bounded outcome and failure categories on `gozleme.auth.attempts` (for example `state_mismatch`, `invalid_token`, `not_linked`). Never record tokens, codes, emails, subject claims or provider error text containing personal data. Audit events use `Gozleme.Security.Audit` with the opaque account id only.

### Demo acceptance

**Demo walkthrough:**
1. With the default stack, show that the sign-in page offers only local sign-in and the OIDC callback returns 404.
2. Start the opt-in test provider, sign in as a synthetic external user, and land on the protected dashboard.
3. Sign in locally, link the external identity, sign out, and sign back in with the provider into the same account.
4. Show that a forged `state`, a replayed code and a token from the wrong issuer are each refused with a generic error.

Include a test exercising the stated important boundary: no identity provider is contacted by the default stack, and an external sign-in never bypasses lockout or revocation.

**Spec complete only when:** code and tests pass; demo is autonomously run or a documented blocker explains why; convergence succeeds; downstream impact is analyzed and applied within authority; PR evidence and screenshots are ready; human merge is later verified.

### Organization and tenancy conventions (GOZ-0002-IF-01, IF-05, IF-06, IF-07, IF-08, 2026-11-15)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0002 at commit `f95be4c` (code as demonstrated at `8a9941e`; findings in `docs/specs/002-organizations/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 1 → 2. These bullets record implemented organization facts and the obligations they create within confirmed architecture; they do not change scope, boundaries, prerequisites or security invariants._

- (IF-05) Tenants are rows of `gozleme.organizations` (`id` uuid UUIDv7, permanent; `display_name` 1–100 chars, **not unique**; no handle, slug, hierarchy, lifecycle or deletion). Membership is a row in `gozleme.memberships` (PK `organization_id, user_id`). It has no role column, and removal deletes the row. An organization-scoped API is mapped under `/api/v1/organizations/{organizationId}/…` with the ID in the path, never taken implicitly from an "active" organization. Its first step is the membership check `OrganizationAccess.FindMembershipAsync` (`src/Gozleme.Api/Organizations/OrganizationAccess.cs:17-25`), or the GOZ-0003/GOZ-0004 successor of that check, read from the database on every request. A malformed ID, an unknown organization and a non-member all get the same empty `404` with `Cache-Control: no-store` (`OrganizationEndpoints.cs:24,45-49`). `activeOrganizationId` from `GET /api/v1/organizations` (`memberships.selected_at`) is a UI preference only and never authority. Web pages for organization data live under `/organizations/[organizationId]/…`, render the existing "Organization not found" page on 404, and build API paths with `segment()` (`web/src/lib/organizations.ts:44`), which neutralises dot segments. A new tenant-owned table carries `organization_id uuid NOT NULL` with a foreign key to `organizations(id)`.
- (IF-01) Until GOZ-0003 merges, tenant isolation is enforced **by application authorization only**: no RLS policy exists on `organizations`, `memberships` or `invitations` (GOZ-0002 plan, Complexity Tracking). Do not claim RLS protection for any data before GOZ-0003 is merged and verified.
- (IF-07) Telemetry and audit precedent: the span attribute `gozleme.organization.id` (opaque UUID) is set only after membership is confirmed and is never a metric label (`OrganizationTelemetry.cs:17,24,38`). Organization display names, emails and invitation codes never appear in spans, metrics, logs or URLs. Security audit event IDs are allocated per module: identity uses 1001–1010 and organizations use 1101–1108 (`src/Gozleme.Api/Identity/SecurityAudit.cs:13-65`). Give a new module its own range. Audit events remain log records only.
- (IF-08) A new rate-limited endpoint must attach `RateLimitedOperation` metadata (`src/Gozleme.Api/Identity/IdentityServiceCollectionExtensions.cs:119-129,163`; pattern `OrganizationEndpoints.cs:38-41`). Without it, the shared `OnRejected` handler records the rejection as a `gozleme.auth` sign-in or register failure. Rate limiters are in memory and per API instance. Partition by account ID when the endpoint requires a session.
- (IF-06) Demo state after the GOZ-0002 suite:
  - `seed` (`src/Gozleme.Api/Identity/OperatorCommands.cs:27-30,122-150`) now also creates `carol@demo.gozleme.test` and the fixed-ID organization **Seeded Demo Org** (`0193a000-0000-7000-8000-000000000002`). Every run restores its name, exactly alice and carol as members, and no invitations. In the e2e suites these are `DEMO.carol` and `DEMO_ORG` (`e2e/tests/evidence.ts`).
  - The `goz-0002` suite never deletes the organizations it creates. Each run leaves alice in three more run-unique organizations (`Demo Org Alpha/Beta Renamed/Solo NNNNNN`). bob ends with no organization.
  - Later suites therefore use fixed seeded organizations, never assert an exact organization count for alice, and sign in afresh.
  - A demo that needs two tenants with disjoint members adds a second fixed-ID organization to `seed`, for example with bob as its member.
  - Use `recentSpans(service, minutes, operation)` (`e2e/tests/telemetry.ts`) to find spans of a named operation. Poll the metrics scrape for up to 90 s for a counter that is first recorded during the suite, because the SDK exports metrics every 60 s.

### Implementation alignment (GOZ-0002-IF-14, 2026-11-15)

_Provenance: added by the post-convergence Spec Impact Analyst for GOZ-0002 at commit `f95be4c` (code as demonstrated at `8a9941e`; findings in `docs/specs/002-organizations/reviews/impact-findings.json`). Roadmap Steward must bump `promptRevision` 1 → 2. These bullets record implemented organization facts and the obligations they create within confirmed architecture; they do not change scope, boundaries, prerequisites or security invariants._

- (IF-14) Organization membership is created only by creating an organization or redeeming an invitation code (GOZ-0002 maintainer decision `join-method`). An external sign-in must not join organizations automatically, and IdP claims such as groups, roles or email domain must not map to membership or GOZ-0004 roles. Such mapping would be new scope needing maintainer approval. A linked OIDC identity acts as the same local account, with the same memberships.
- (IF-01) Maintainer decision (2026-11-15): this spec may be built before GOZ-0003 only because it adds no organization-scoped data. Its identity-link tables are global (account-level); classify them on the GOZ-0003 non-tenant allow-list. If the design ever needs an organization-scoped table or column, wait for GOZ-0003.
